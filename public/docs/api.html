API basics

One address, one key header, JSON in and out. Pranata V1 answers on an endpoint of its own; the roleplay models speak the chat format the OpenAI SDKs already use.

On this page

  • Base URL
  • Your key
  • Endpoints
  • Model IDs
  • With the OpenAI SDKs
  • Request IDs
  • Errors
  • Retries and limits

Base URL

Base URL
https://ai.zeiko.biz.id/v1

Every path below starts from it. Your account's API key page shows the same address beside your key.

Your key

Send your key on every request, in the Authorization header:

Header
Authorization: Bearer YOUR_API_KEY
  • Pranata V1 keys come from your account. Keys for the roleplay models are requested by email.
  • Keep the key on your server, in an environment variable such as ZEIKO_API_KEY, never in your code, a web page or a mobile app.
  • If a key may have leaked, replace it: Make a new key in your account, or email us for a roleplay key. The old key stops working at once.

Endpoints

MethodPathKeyWhat it does
GET/v1/modelsNot neededLists the models.
GET/v1/models/{id}Not neededOne model, or 404.
POST/v1/decisionsNeededAsks Pranata V1. See the Decisions API.
POST/v1/chat/completionsNeededChat with a roleplay model, streamed or not. See the Chat API.

Each model answers on its own endpoint: a roleplay model sent to /v1/decisions, or Pranata V1 sent to /v1/chat/completions, is refused with 400 wrong_endpoint before anything is used.

IDs are lowercase and must be sent exactly as written. GET /v1/models always has the current list, and needs no key:

curl
curl https://ai.zeiko.biz.id/v1/models

Each entry carries the model's id, its context_length and its prices per token, as decimal strings (read them as decimals, not floats). Use the fields you need and ignore the rest.

With the OpenAI SDKs

For the roleplay models, point any official OpenAI SDK at the base URL and give it your key:

Python
import os
from openai import OpenAI

client = OpenAI(
    base_url="https://ai.zeiko.biz.id/v1",
    api_key=os.environ["ZEIKO_API_KEY"],
)
JavaScript
import OpenAI from "openai";

const client = new OpenAI({
  baseURL: "https://ai.zeiko.biz.id/v1",
  apiKey: process.env.ZEIKO_API_KEY,
});

Pranata V1's decisions are plain JSON over HTTPS: call them with any HTTP client. There are examples in the Decisions API.

Request IDs

Every answered request carries an X-Request-Id header; a chat reply also carries it as its id. Keep it: if you write to us about a request, include it. For an error, which has none, include the time, the model and the status code.

Errors

An error comes back with a matching HTTP status and a JSON body:

Error
{
  "error": {
    "message": "model \"jagad-512b-v2\" is not available",
    "type": "invalid_request_error",
    "code": "model_not_found"
  }
}

message is written for people; code is the one to check in your code. Each endpoint lists its own codes: Decisions API, Chat API.

StatusWhat it meansRetry?
400 404 413 422Something in the request. Fix it first.No
401 403The key: missing, unknown, turned off, or not allowed that model.No
402Not enough balance for a Pranata V1 call.After adding balance
429Too many requests, a limit reached, or the model is busy.Yes, after Retry-After
500 502 504Something went wrong on our side.Yes, two or three times

Retries and limits

  • 429: wait as many seconds as the Retry-After header says. Without it, back off: start at about a second and double each time.
  • 500, 502, 504: retry two or three times, with the same backoff.
  • Any other 4xx: do not retry. Fix the request or the key first.

A key can carry a per-minute limit and a daily quota; reaching either is a 429 rate_limit_exceeded. If you need more, write to admin@zeiko.biz.id.
